# Guardrails

Daedalus does not let a guarantee rest on someone's word, memory or good behaviour. Each rule is built so the plugin enforces it and can show that it holds. A limit sits where it cannot be skipped. Each fact has one owner, and every other copy is computed from it. A claim waits until a mechanism stands behind it, and a check outranks an argument. Every change leaves a record. Where a rule is relaxed, the relaxation is written down with the condition that ends it.

## How to read a row

Each row pairs a principle, in words, with the mechanism that enforces it and the tests that show the mechanism exists. A reference in backticks is a file path relative to the plugin root. A path followed by `::` and a name points inside that file. In a Python file the name is a function, a class or a module-level value. In any other file it is text the file contains. A test reference names a test function in its test file. Ruling ids and issue numbers trail in parentheses (0031). A known gap in a mechanism is named in its row with the issue that tracks it.

## Checking the table

Does every row still name code that exists? Run this from the plugin root of a clone; it needs no credential:

    python3 -m pytest tests/test_guardrails.py -q

A pass means every file, name and test the table cites exists. A failure names the row's line and each missing item. An import error means the command ran outside the plugin root.

The tests a row names prove the behaviour. The full suite runs them, from the same folder:

    python3 -m pytest tests -q
