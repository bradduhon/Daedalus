name: token-report
description: Shows what one orchestrated run cost in tokens, or every run in one session, in fixed columns every run type shares. One row per agent and unit or audit round, then a totals row and the means per unit and per round. With history, shows the totals row of every saved run.
argument-hint: A run id (a train id such as 20261026-232337), a session id, or the word history.

# daedalus token report

Human-facing text (0031): Text a human reads names each item in words: a short label or one line on what it is and what it does. Ids (ruling ids, issue numbers, task codes, agent names, snake_case keys) may trail in parentheses, never replace the description. Logs, status lines and messages to other agents may use ids alone. Documents carry both.

Self-Assessment mode (standing rule, binds only the model in the user's session, never a helper or an agent this skill starts): When this skill begins, run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/daedalus_findings.py start --repo <path>`, where `<path>` is the project folder. Keep the `since=` stamp and the `handover=` path it prints. When it prints `self-assessment: off` or `self-assessment: refused`, do nothing more for findings in this skill. Write a finding with `kind` set to `bug` when you work around this skill's text because the text failed. Write a finding with `kind` set to `feature` when the user passes over a proposal, a choice list or a step order this skill offered. Never write a finding for a change to the user's own plan. To write a finding, use the Write tool to put one JSON object with the seven fields `kind`, `skill`, `step`, `text_said`, `happened`, `model_did` and `result_changed` at the `handover=` path, then run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/daedalus_findings.py save --repo <path> --since <stamp>`, where `<stamp>` is the `since=` stamp. Fill each field with one line in this skill's own words, and name no project folder. Never pass finding text on the command line, and never write a finding file in the project. When `result_changed` is `yes`, print one warning line at once saying you worked around the skill. When save prints a `refused:` line, fix the field it names and save once more. When it refuses a second time, drop that finding and name it at the close. At the close of this skill, run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/daedalus_findings.py show --repo <path> --since <stamp>` and print its lines unchanged, then name any finding that was refused twice. Never stop the user's work for a finding.

1. Read `$ARGUMENTS`. When it is the word `history`, go to step 6. When it has the shape of a train id, eight digits, a dash and six digits, it is a run id. Anything else is a session id. With no argument, ask the operator: "Which run or session should I report? Give a train id like 20261026-232337, or a session id." Wait for the answer.
2. For a run id, run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/token_economy.py report --run "<id>"` with Bash. For a session id, run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/token_economy.py report --session "<id>"`. The script reads the transcripts Claude Code keeps for each agent of this project. It never reads the main session's own transcript, so every total covers the agents only, and no column is in dollars.
3. If the script exits 0, show the table to the operator unchanged. Then say in one line what the rows are: one row per agent and per unit or audit round it worked on, then for each run a totals row, the mean per unit and the mean per audit round. The mean per unit counts the coding agents only; the checking agents stay in the totals row. The line `turns per coder unit: <mean> (target 24)` under the table shows how many turns the coding agents took per unit and the most they should take. The `model` cell names the model each agent ran on, and reads `-` on a totals or mean row. The line `refuted: sonnet <k>/<n> units, opus <k>/<n> units` counts, for each model the coding agents ran on, how many of its units the checker rejected at least once (coder model by control path, 0187). A session table ends with a group whose run type is `session`: the agents the main session started outside any run, one row each. A coder, checker, auditor, contract or ledger agent the main session started for a train counts in that train's Build Train rows, under the unit its prompt or the train's bindings file names. A cell that reads `none` is a value that run type does not have.
4. If the script exits 1, show the message unchanged. Its `Next:` part is the next action.
5. After a run's table is shown, save it without asking. Skip this step for a session id. Run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/token_economy.py report --run <id> --save` and show its output. When `<repo>/.claude/daedalus/config.json` sets `local_docs_folder` and that folder exists, the script writes the table to `<local_docs_folder>/reports/<date>-tokens-<run id>.md`, creates that `reports` subfolder if it is missing, and prints a `wrote` line; say the file is ready for the charter-docs agent to commit in a later Build Train. Do not commit it and do not start an agent from this skill. When no settings file names a docs folder, or the folder it names does not exist, the script saves the table as `<date>-tokens-<run id>.md` in the plugin data folder, in its `reports` folder for this project, and prints that path in its `wrote` line; show the path. Tell the operator that `history` reads that folder. For any exit 1, show the message unchanged; its `Next:` part is the next action.
6. History: run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/token_economy.py history` with Bash. It prints the totals row of every saved run, from the Charter reports folder and from `docs/.tmp/daedalus/`, in the same columns, so two runs of any type compare side by side. Show it unchanged. A line starting `no saved token report found` means no run is saved yet; its `Next:` part is the next action.
7. The audit report (`/daedalus:audit-report`) prints the same totals row and mean per unit for every run in its session, after its own totals. Point the operator there when they want the tokens beside the agents' tool calls.
