# daedalus audit report

Human-facing text (0031): Text a human reads names each item in words: a short label or one line on what it is and what it does. Ids (ruling ids, issue numbers, task codes, agent names, snake_case keys) may trail in parentheses, never replace the description. Logs, status lines and messages to other agents may use ids alone. Documents carry both.

Self-Assessment mode (standing rule, binds only the model in the user's session, never a helper or an agent this skill starts): When this skill begins, run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/daedalus_findings.py start --repo <path>`, where `<path>` is the project folder. Keep the `since=` stamp and the `handover=` path it prints. When it prints `self-assessment: off` or `self-assessment: refused`, do nothing more for findings in this skill. Write a finding with `kind` set to `bug` when you work around this skill's text because the text failed. Write a finding with `kind` set to `feature` when the user passes over a proposal, a choice list or a step order this skill offered. Never write a finding for a change to the user's own plan. To write a finding, use the Write tool to put one JSON object with the seven fields `kind`, `skill`, `step`, `text_said`, `happened`, `model_did` and `result_changed` at the `handover=` path, then run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/daedalus_findings.py save --repo <path> --since <stamp>`, where `<stamp>` is the `since=` stamp. Fill each field with one line in this skill's own words, and name no project folder. Never pass finding text on the command line, and never write a finding file in the project. When `result_changed` is `yes`, print one warning line at once saying you worked around the skill. When save prints a `refused:` line, fix the field it names and save once more. When it refuses a second time, drop that finding and name it at the close. At the close of this skill, run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/daedalus_findings.py show --repo <path> --since <stamp>` and print its lines unchanged, then name any finding that was refused twice. Never stop the user's work for a finding.

1. Run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit_report.py --session "<id>"` with Bash, where `<id>` is `$ARGUMENTS` when the operator gave one; otherwise omit `--session` and tell the operator it reports the newest session log for this repo. The script checks the hash chain before it renders anything.
2. If the script exits 0, show the digest to the operator unchanged. Take `<session>` from the digest's `session:` line, with any backslashes removed; steps 5 to 7 use it.
3. If the script exits 1 with a `BROKEN` line, show that line and nothing else from the log. Tell the operator the audit log failed its chain check, so a record was changed, removed, or reordered after it was written. The operator can rerun the check by hand with `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/verify_audit_chain.py <repo>/.claude/daedalus/audit/<session>.jsonl`, where `<session>` is the id given or, with none given, the newest `.jsonl` in that directory. Then give the three next actions: keep the file, report it, do not edit it.
4. If the script exits 1 with any other message, show the message unchanged. Its `Next:` part is the next action.
5. After a digest is shown, save the report without asking. Run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit_report.py --session <session> --save`. The script reads `<repo>/.claude/daedalus/config.json` (`<repo>` is the main working tree; a linked worktree shares that file). When it sets `local_docs_folder` and that folder exists, the script renders the report again, writes it to `<local_docs_folder>/audit/<session>.md`, creates that `audit` subfolder if it is missing, and prints a `wrote` line. It never creates the docs folder itself. Name the session so a newer log cannot take its place; a live session will have gained a few records since the digest on screen. For any exit 1, show the message unchanged; its `Next:` part is the next action. On success, show the `wrote` line, then say the file is ready for the charter-docs agent to commit in a later Build Train. Do not commit it and do not start an agent from this skill.
6. When no settings file names a docs folder, or the folder it names does not exist, the script saves nothing and prints the report and one line saying no docs folder is set. Say the digest stays on screen only. Name the raw log: `<repo>/.claude/daedalus/audit/<session>.jsonl`. Next: run `/daedalus:audit-report <session>` again to see it.
7. Steps 2 to 4 judge the log; step 5 checks the chain again inside the script before it writes.
8. Control cost table: when the operator or a Build Train asks only for what the controls cost, run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit_report.py --repo <repo> --session <session> --controls`. It checks the hash chain first, as step 1 does, then prints only the `Control cost` section: blocks per refusing hook with the agent type, then each refusing hook once with its `failure:` line (the failure that hook prevents, from the controls fragments under `scripts/checks/controls/`, or `failure: none` when no row names one), the seconds from each block to that agent's next allowed call, the seconds from each agent's start to its first allowed Write or Edit, and the mean time the jail took to judge a call. The full digest of step 2 carries the same section. Exit 1 is handled as in steps 3 and 4.
